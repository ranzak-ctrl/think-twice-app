Slot = **פריט מידע יחיד שהשלב חייב לקבל עליו תמונה**. זו "תא" ב-Scorecard הנסתר שהמערכת מנהלת מאחורי הקלעים — בדיוק כמו גיליון הדירוג של המאבחנת בראיון צו ראשון: השיחה זורמת חופשי, ומאחור יש רשימת ממדים שצריך למלא. **ההיגיון** (מ-[transition-protocol.md §2](docs/transition-protocol.md)): כל שלב = נושא במדריך הראיון. לכל נושא יש **Core Slots** — תתי-הפריטים שחובה לכסות. הם חיים בשכבת `coverage` ב-State, **נסתרים מהמשתמש**, ומדורגים בסולם אחיד: - **0** — לא נגעו - **1** — נגיעה חלקית / עמום - **2** — ברור ומאושש - **U** — Unknown לגיטימי ("לא יודע / לא זוכר") — ערך **סופי תקין**, לא חוסר **בקוד** ([state.js:16](src/core/state.js:16)) זה אובייקט מילולי. למשל שלב 1: ``` stage1: { trigger: 0, timeline: 0, actors: 0, status: 0, auto_reaction: 0 } ``` כל מפתח הוא Slot; הערך הוא הציון. המודל מדווח ציונים בכל תור; ה-Router קורא אותם. **איך עובד Slot בפועל** — דוגמה מהתמליל, שלב 1, ה-slot `timeline`: - בהתחלה 0. - המשתמש: "יומיים לפני הארוחה, תוך כדי שהתארגנו" → יש התחלה, **1**. - אחרי שהתבררו האמצע (השיחה) והסוף ("לפני שעתיים, לא דיברו מאז") → ציר זמן שלם, **2**. - Slot עובדתי עולה ל-2 רק אם עבר את **מבחן המצלמה** (משהו שמצלמה הייתה קולטת), לא פרשנות. **למה זה הלב של ה-Router**: ההכרעה על מעבר שלב היא חישוב על ה-Slots — "סף רך" ([router.js:52](src/core/router.js:52)): כל ה-Core Slots ≥ 1 ורובם (~80%) ב-2. זה המימוש של "המודל מציע, הקוד מכריע" — ה-LLM נותן ציונים, הקוד סופר ומחליט. **והקשר לסתירות שדיברנו עליהן**: "Re-open" = בדיוק **להוריד ציון של Slot** (2→1, מה ש[`reopenSlot()`](src/core/state.js:109) עושה). מידע סותר מחזיר slot שכבר היה "מאושש" למצב "עמום" — וכך השלב כבר לא ממוצה, והנושא נפתח שוב. לכן ההכרעות בשתי השאלות הקודמות הן בעצם "על איזה Slot, ומתי, מורידים ציון".
