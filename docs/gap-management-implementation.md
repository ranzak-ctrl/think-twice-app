# ניהול פערים — אפיון יישום

**מעמד:** אפיון מאושר · עודכן 21.6.2026 · נגזר מהתפיסה ב-[gap-management.md](gap-management.md)
**עיקרון:** המודל מדווח פערים מדורגים; ה-Router/קוד מתעד, מכריע ומנתב — **לעולם לא המודל**.
**מחליף:** את `flag_contradiction` הבינארי ואת `reopenSlot()` שאינו נקרא. סוגר את חוסם הסתירות (dev-plan §5). *גלאי העייפות נפרד.*
**שפה:** פרוזה בעברית; מזהי שדות/קוד באנגלית (קונבנציית הריפו).

---

## 1. המדד — "ציון עקביות" 1–10

לכל **יעד** (slot, נושא או יישות) שנגעו בו, המודל מדווח ציון עקביות:

```
10 ── עקבי        מידע מלא, אמין, מתיישב
 …
 5 ── עמום        חוסר עקביות / גמישות / חוסר היגיון חלקי
 …
 1 ── סתירה       היפוך מלא של עובדה או עמדה
```

גבוה = קוהרנטי, נמוך = פער. הציון נמדד **פר מישור** (`dimension`): `factual` / `emotional` / `cognitive`. המודל מדווח ציון **רק כשיש אות עקביות** (ברירת מחדל: לא מדווח = עקבי); **רשומה נוצרת רק לפער** (`level ≤ T_star`). המגמה (עלייה/ירידה) נשמרת ב-`history` של יעד שכבר נפתח — והיא הדאטה (gap-management §5–6).

## 2. סכמת ה-state — `gaps`

נוסף ל-`createState()` (state.js), top-level (כמו `basket`/`board`):

```js
gaps: {
  byTarget: {
    // key: "stage1.timeline" | "topic:בשר" | "entity:החבר"
    "<targetKey>": {
      target:    { kind: 'slot'|'topic'|'entity', stage, slot, label },
      dimension: 'factual'|'emotional'|'cognitive',
      level:     1..10,                     // ציון עקביות נוכחי
      status:    'starred'|'escalated'|'resolved',
      firstTurn, lastTurn,
      touches:   0,                         // נגיעות חוזרות אחרי היצירה
      history:   [{ turn, level }],         // סדרת הזמן — המקור למגמה
      note:      ''
    }
  },
  log: [{ turn, targetKey, level, delta, action }]  // עקבה למצב מדריך
}
```

`targetKey` מנורמל: slot → `stage{N}.{slot}`; נושא/יישות → `topic:{label}` / `entity:{label}` (trim, dedup). **רשומה אחת לכל `targetKey`** — תצפית חדשה תמיד מעדכנת את הקיימת, לעולם לא משכפלת.

**מקור מול נגזר:** `history` הוא המקור היחיד. `level` (=האחרון), `firstTurn` (=הראשון), `lastTurn` (=האחרון), `touches` (≈ אורך−1) — כולם **נגזרים** ממנו; נשמרים denormalized לקריאוּת (מצב מדריך + ייצוא). **קבועים** מרגע היצירה: `target`, `dimension`, `firstTurn`. **משתנים**: `level`, `status`, `touches`, `lastTurn`, `history`, `note`.

## 3. צד המודל — קלט ופלט

### 3.1 מה נשלח למודל בכל תור (קלט)

עיקרון: הקוד **אוצֵר** את ההקשר — לא שולחים את כל מאגר הפערים, אלא רק מה שדרוש (כלכלת-הקשר, dev-plan סיכון #3).

**נשלח:**
- **העובדות המבוססות** (`facts`/`coverage` — כבר בתמצית ה-state). מכאן המודל *מזהה* סתירות חדשות ושבירות-מחדש, מול מה שכבר נקבע.
- **רשימת ה"לחזור אליו"** — `escalated` עם reprobe דחוי **בלבד** (לא כל `starred`!). שורה ליעד: תווית + `note`. מסומן "מאחורי הקלעים — אל תחשוף למשתמש".
- **הוראת reprobe מפורשת** — כשהקוד החליט על ניתוב-בחזרה ליעד מסוים (escalated + פתח אלגנטי).

**לא נשלח:**
- פערים `resolved` — עקביים כרגע; תוכנם נישא ממילא ב-`facts`.
- פערים `starred` לא-מהותיים — נרשמים ולא נרדפים (gap-management §10.1); אין סיבה להעמיס אותם על המודל.
- שדות בוקקיפינג: `history`, `touches`, `level`, `firstTurn`/`lastTurn`, `status` — state פנימי של הקוד בלבד.

**שתי משימות, שני מקורות:**

| משימת המודל | מקור בפרומפט |
|---|---|
| לזהות פער חדש / שבירה-מחדש | העובדות המבוססות (`facts`/`coverage`) |
| לחזור ליעד פתוח | רשימת ה"לחזור אליו" (escalated-pending) |

פורמט הרשימה בפרומפט:
```
## לחזור אליהם (מאחורי הקלעים — אל תחשוף למשתמש)
- ציר הזמן (שלב 1): לא ברור מה קרה אחרי הניתוק. כשיש פתח — ברר בעדינות.
```
(מקביל למנגנון `savedThreads` הקיים — חוטים פתוחים לחזרה.)

### 3.2 מה המודל מדווח (evaluator.md, פלט)

המודל מחזיר **תצפית נקודתית בלבד** — אינו מנהל את הרשומה. מחליפים `flag_contradiction: bool` ב-`gap_observations`:

```json
"gap_observations": [
  { "target": "stage1.timeline", "dimension": "factual", "level": 3, "note": "סדר התגובות הפוך ממה שנמסר קודם" }
]
```

המודל שולח רק `target`+`dimension`+`level`+`note`. את `status`/`touches`/`history`/timestamps — **הקוד** מחזיק ומעדכן (§4).

הנחיות למודל:
- דווח ציון עקביות (1–10) ליעדים שנגעת בהם **רק כשיש מה לומר** (ברירת מחדל: לא לדווח = עקבי).
- 10 מלא ועקבי · 5 עמום · 1 סתירה ישירה.
- היעד = מזהה slot שאתה מכיר, או תווית נושא/יישות.
- **אי-הלימה עובדתית-יסודית → הבהר בזרימה, באותו תור**, בעדינות ובלי עימות (זהו המקור למיידיות; §4 מסלול מיידי).
- **מאחורי הקלעים בלבד** — לעולם אל תשקף את הפער למשתמש (gap-management §1).
- **הסתייגות ADHD:** שכחה/פיזור אינם "סתירה". דווח ציון נמוך רק על אי-הלימה ממשית (gap-management §9).

responseParser.js: לפרסר `gapObservations` (לאמת shape, clamp 1–10). `flagContradiction` → ממופה לאחור כ-observation ברמה 1 (תאימות), ואז מוסר.

## 4. מחזור החיים — הכוכבית

**חלוקת תפקידים:** המודל שולח תצפית נקודתית; **הקוד מנהל את הרשומה** — סטטוס, מונים, history — ומעדכן **רק בתור שבו נגעו ביעד מחדש** (אחרת הרשומה יושבת ללא שינוי).

```
תצפית חדשה על יעד
   │
   ├─ level > T_star  והיעד לא ברשומות   → להתעלם (עקבי דיו, אין רשומה)
   │
   └─ level ≤ T_star  → ליצור/לעדכן רשומה (history, level, lastTurn, touches)
        │
        └─ מבחן המטרה מיד (§5):
             ├─ יסודי/חוסם → status 'escalated' (N_touches=0) + reopenSlot מיידי   [מסלול מיידי]
             └─ אחרת        → status 'starred'  (נרשם, לא נפעל)                    [ברירת מחדל]

נגיעה חוזרת ביעד קיים:
   ├─ level ≥ T_resolved                  → status 'resolved'  (נפתר — §10.2)
   └─ נשאר ≤ T_star ו-touches ≥ N_touches
        └─ ומבחן המטרה חוסם (§5)          → status 'escalated' (§10.3)

יעד 'resolved' שמקבל תצפית סותרת חדשה:
   └─ אותו targetKey נפתח מחדש → 'starred' (או 'escalated' אם יסודי) + reopenSlot שוב
      ('resolved' אינו סופי; רשומה אחת לכל יעד, ה-history ממשיך)
```

**שני מסלולים:**
- **מיידי** (יסודי/חוסם) — המודל מבהיר בזרימה באותו תור (§3.2); הקוד מסלים, פותח slot מיד וחוסם מעבר. *המיידיות מהמודל; הערובה מהקוד.*
- **ברירת מחדל** (לא-מהותי) — כוכבית: נרשם, רוב הפערים נפתרים לבד, ולא נרדפים.

---

## 5. מבחן המטרה — מתי מסלימים (goal-gate)

נבדק **בכל תצפית** (כולל הראשונה — המסלול המיידי). הסלמה ל-`escalated` רק אם הפער **חוסם את העזרה** (gap-management §10.1). שני תנאים, כל אחד מספיק:

1. **יעד יסודי** — slot שעליו נשענת העבודה הטרנספורמטיבית. **ננעל (21.6):** כל ה-Core Slots של שלב 1 (עובדות המקרה) — "בלי עובדות אין סיפור לעבוד איתו". הרחבה ל-`stage2.causal` / `stage2.wound` ומעבר נותרה פתוחה לחשיבה (§12.1). ("תיאוריה מדעית על מידע שגוי".)
2. **חוסם מעבר** — היעד מונע מ-`softThresholdMet` של השלב הרלוונטי להתקיים (router.js).

**"מהותי" מוכרע ע"י הקוד** (זהות היעד / חסימת סף), לא ע"י המודל. יעד לא-יסודי ולא-חוסם → נשאר `starred` (נרשם, לא נפעל).

---

## 6. ניתוב-בחזרה — reprobe + תזמון אלגנטי

**רק** ל-`escalated` שה-reprobe שלו **נדחה לתזמון אלגנטי** — פער יסודי שלא היה נכון לקטוע בגינו את הרגע (למשל באמצע פורקן רגשי). פער שטופל מיד (§4 מסלול מיידי) אינו נכנס לכאן.

כשיעד `escalated` ממתין, ה-Router מסמן `revisitPending`. session/promptBuilder מזריקים הוראת reprobe:

- "חזור אל **{topic}** מתוך עניין כן; שאל שאלה פתוחה אחת שתמלא את החסר. **אל תעמת** עם אי-ההלימה." (ניסוח = תוכן, נשען על gap-management §10.3–10.4.)
- **תזמון אלגנטי:** `revisitPending` מחזיק budget של `K_wait` תורות — הסוכן רשאי לשזור באופן טבעי; אם לא טופל תוך K, מאלצים reprobe עדין. המודל מדווח `revisit_addressed: true` כשטיפל.
- בהצלחה (level עולה) → `resolved`.

---

## 7. חיווט `reopenSlot` (מדורג)

`reopenSlot(state, stageKey, slot)` (state.js, כיום לא-נקרא) נקרא בהסלמה על יעד-slot — כולל המסלול המיידי וכולל re-open של `resolved`: מוריד 2→1, פותח מחדש את הנושא וחוסם מעבר. המדד המדורג מחליט *מתי* — לא דגל בינארי גולמי.

---

## 8. נראות במצב מדריך (GuidePanel.jsx)

סקשן חדש "פערים / כוכביות": לכל יעד — תווית, `level` (1–10), חץ-מגמה (▲/▼), `status`, מספר `touches`. ותקציר דפוסים (סעיף 9). עקבי עם הצגת ה-signals/coverage היום.

---

## 9. דפוסים — אגרגציה (gap-management §6)

נגזר מ-`byTarget` + `history`:
- **מגמה ליעד** — level לאורך הזמן (גדל/קטן); כולל סאגת `resolved → שבירה מחדש` כסיגנל חזק.
- **פילוח מישור** — היכן הפערים מרוכזים (factual מול emotional/cognitive).
- **לפי יישות/נושא** — "מדיניות הפערים" סביב דמויות/נושאים שונים.

Phase 1: אגירה + תצוגה במדריך. Phase 3: בין-ראיוני (תלוי persistence).

---

## 10. סדר הבנייה (פאזות)

- **Build 1 — המדד + הכוכבית, מאחורי הקלעים.** evaluator/parser/state, `gaps.byTarget`, record+star (כולל re-open של resolved), תצוגה במדריך. אפס שינוי בחוויית המשתמש. מחליף את הדגל הבינארי.
- **Build 2 — הסלמה + ניתוב.** goal-gate (§5), מסלול מיידי + סף חזרתיות, `revisitPending`+reprobe (§6), חיווט `reopenSlot` (§7), הוראת-העל למודל (§3.2).
- **Build 3 — עתידי.** דפוסים מצטברים עשירים + בין-ראיוני.

---

## 11. בדיקות

- **state** — lifecycle של `gaps` (create→star→resolve→escalate→**re-open**); רשומה אחת לכל `targetKey`; סבב ייצוא/ייבוא משמר `gaps`.
- **Router** — מטריצת המעברים המלאה (כל שינוי router); מסלול מיידי על יעד יסודי (N=0); הסלמה רק תחת goal-gate; reopenSlot מדורג.
- **פרומפט** — תסריטי זהב + שופט-LLM (כל שינוי evaluator); תסריט סתירת-הבשר (התמליל) כ-fixture.
- **lint** — reprobe לא יוצר תפריט/עימות; שאלה אחת בדיוק.

## 12. ספים ופרמטרים — מאושר (21.6.2026)

ערכי ברירת המחדל אושרו; כולם tunable וראויים לוולידציה מול נתונים.

| פרמטר | תפקיד | ערך | Build |
|---|---|---|---|
| `T_star` | `level ≤` זה → נוצרת רשומת פער (כוכבית) | **5** | 1 |
| `T_resolved` | `level ≥` זה בנגיעה חוזרת → נפתר | **8** | 1 |
| `N_touches` | נגיעות בלי שיפור לפני הסלמה (במסלול הלא-מיידי) | **2** | 2 |
| `K_wait` | חלון התקדמות לפני reprobe מאולץ (ראו 12.1) | **3** | 2 |
| יעדים יסודיים | מי "חוסם" לפי §5 | **stage1.\*** (כל עובדות המקרה) | 2 |

**Build 1 תלוי רק ב-`T_star` + `T_resolved`.** שלושת האחרים נכנסים ב-Build 2 (הסלמה+ניתוב); לכן הנקודות הפתוחות שלהלן **אינן חוסמות את Build 1**.

### 12.1 נקודות שנותרו פתוחות ל-Build 2

1. **`K_wait` — להמשיג מחדש (אינו מנגנון מדויק כרגע).** השאלה אינה "כמה תורות להמתין עד שחוזרים לבירור" אלא **עד כמה אפשר להתקדם בראיון בלי להשלים את הפער**. כלומר לא טיימר-תורות אלא סף-התקדמות: הפער נשאר פתוח עד שאי-השלמתו חוסמת מעבר/התקדמות. לתכנן ב-Build 2 כנגזרת של מבחן-המטרה (§5 / gap-management §10.1), לא כמונה תורות.
2. **יעדים יסודיים — דורש חשיבה מעמיקה.** הננעל כעת = `stage1.*` בלבד ("בלי עובדות אין סיפור לעבוד איתו"). הרחבה ל-`stage2.causal` / `stage2.wound` ומעבר נותרה פתוחה — `wound` במיוחד רגיש ועשוי להתייצב מאוחר בראיון, וחסימה מוקדמת עליו עלולה לתקוע דווקא את החלק העדין. להכריע לפני Build 2.
